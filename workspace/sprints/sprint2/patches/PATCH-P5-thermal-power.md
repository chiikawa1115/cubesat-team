# PATCH-P5：電池低溫容量 + 熱控-電力連鎖分析

## 0. 問題陳述

詹教授於 PDR 審查指出三項連鎖風險：

1. **B-008 熱控**：Eclipse-end 電池溫度 -8.3°C，距 -10°C 下限餘裕僅 1.7°C
2. **Li-ion 低溫容量衰退**：-8.3°C 時電池有效容量再降 ~22%，使 EOL effective 容量遠低於名目 8.0 Wh
3. **熱控-電力連鎖**：若加熱器升至 0.75W 改善溫度餘裕，EOL 能量赤字從 -0.040 擴大，M1 mitigation 更難解

此為 **系統層級交叉驗證（cross-domain coupled analysis）** 問題，非單一子系統可獨立處理。

## 1. Li-ion 低溫容量衰退分析（Analysis A）

### 1.1 電池基本規格（B-005 Section 5.1）

| 參數 | BOL | EOL (3 yr) |
|------|:---:|:----------:|
| 標稱容量 | 10.0 Wh | 8.0 Wh |
| 標稱電壓 | 7.2V (2S) | 7.0V |
| 容量衰減率 | — | 20%（500+ cycles, 30% DoD） |
| 操作溫度範圍 | -10°C ~ +50°C | -10°C ~ +50°C |
| 允許 DoD 上限 | 30% | 30% |

### 1.2 Li-ion 低溫容量特性（工業通用數據）

Li-ion 電池在低溫下因電解液離子遷移率降低、SEI 膜阻抗增大，可用容量顯著下降：

| 溫度 (°C) | 相對於 25°C 的可用容量 (%) | 來源 |
|:---------:|:--------------------------:|------|
| +25 | 100% | 標稱（datasheet 額定值） |
| +10 | ~95% | 一般 18650 Li-ion |
| 0 | ~85% | 工業共識 |
| -5 | ~80% | 內插估算 |
| -8.3 | **~78%** | 內插：0°C→-10°C 線性插值 |
| -10 | ~73% | 操作下限，容量嚴重衰退 |
| -20 | ~55-60% | 超出操作範圍，可能析鋰 |

> **內插方法**：在 0°C (85%) 與 -10°C (73%) 之間，取 -8.3°C 線性內插：
> 73% + (85% - 73%) × (10 - 8.3)/10 = 73% + 12% × 0.17 = 73% + 2.04% = **75.0%**
>
> 考慮不同來源數據差異（0°C 容量 82-88%，-10°C 容量 70-76%），取保守值 **~75%** 進行後續計算。修正自原始估算的 78%，採用更保守假設。

### 1.3 EOL + 低溫 Combined 容量

```
有效容量 = BOL容量 × EOL衰減 × 低溫衰減
         = 10.0 Wh × 0.80 × 0.75
         = 6.00 Wh
```

| 項目 | 名目 EOL (25°C) | 實際 EOL (-8.3°C) | 差異 |
|------|:---------------:|:-----------------:|:----:|
| 有效容量 | 8.00 Wh | **6.00 Wh** | -25.0% |
| 最大可用能量 (30% DoD) | 2.40 Wh | **1.80 Wh** | -25.0% |

### 1.4 DoD 修正（基於 B-005 精確數字）

B-005 Section 5.3-5.5 的 DoD 計算均基於 EOL 容量 8.0 Wh。需以 6.00 Wh 重算：

**修正因子** = 8.00 / 6.00 = **1.333**

| 場景 | 放電量 (Wh) | 原 DoD (EOL 8Wh) | 修正 DoD (EOL 6Wh, -8.3°C) | 判定 |
|------|:-----------:|:----------------:|:--------------------------:|:----:|
| Eclipse 正常（B-005 §5.3） | 1.785 | 22.31% | **29.8%** | MARGINAL |
| Worst case 單圈（B-005 §5.5） | 2.272 | 28.4% | **37.9%** | **FAIL (>30%)** |
| 連續 3 Eclipse（B-005 §5.4） | 5.355 | 66.9% | **89.3%** | FAIL（非設計場景） |

> **Eclipse 正常放電詳細計算**：
> - Eclipse 功耗 = 3.00 W（B-005 §3.1，含 OBC 1.50 + EPS 0.30 + ADCS 0.50 + TT&C 0.20 + Heater 0.50）
> - Eclipse 時間 = 35.7 min = 0.595 hr
> - 放電量 = 3.00 × 0.595 = 1.785 Wh
> - 修正 DoD = 1.785 / 6.00 = **29.8%**
>
> **Worst case 單圈放電詳細計算**（Contact window 在 Eclipse 內）：
> - Eclipse 非 contact 段：3.00W × 31.7/60 = 1.585 Wh
> - Eclipse 內 contact 段：10.30W × 4.0/60 = 0.687 Wh
> - 合計放電 = 1.585 + 0.687 = **2.272 Wh**
> - 修正 DoD = 2.272 / 6.00 = **37.9%**

### 1.5 結論

**正常 Eclipse DoD = 29.8%** -- 勉強在 30% 限值內，但 margin 僅 0.2%，工程上不可接受。

**Worst case 單圈 DoD = 37.9%** -- 超過 30% 限值 7.9 個百分點。這是 **critical issue**，B-005 的 DoD 分析因未考慮低溫容量衰退而過於樂觀。

## 2. 加熱器升級的連鎖影響（Analysis B）

### 2.1 問題結構

加熱器功率↑ → 電池溫度↑ → 低溫容量衰退改善 → DoD↓（好的方向）
加熱器功率↑ → Eclipse 耗電↑ → EOL 能量赤字↑ → DoD↑（壞的方向）

兩個效應方向相反，需量化哪個占主導。

### 2.2 三情境比較

**共通假設**：
- B-008 lumped model：tau = 44.5 min，T_sunlit = 290.3K (+17.2°C)
- 加熱器僅在 Eclipse 期間運作（35.7 min）
- EOL 基線能量赤字 = -0.040 Wh/orbit（B-005 §4.3）

#### 情境 1：加熱器 0.5W（現狀 — B-005/B-008 基線）

| 項目 | 數值 | 來源 |
|------|------|------|
| Eclipse-end 電池溫度 | **-8.3°C** | B-008 §4.7 |
| 溫度餘裕（距 -10°C 下限） | 1.7°C | B-008 §5.2 |
| Li-ion 容量因子 (-8.3°C) | ~75% | §1.2 內插 |
| EOL effective 容量 | 10 × 0.80 × 0.75 = **6.00 Wh** | |
| 加熱器 Eclipse 耗電 | 0.50 × 35.7/60 = **0.298 Wh** | 已含在 B-005 基線 |
| EOL 能量收支 | **-0.040 Wh/orbit** | B-005 §4.3 |
| 正常 Eclipse DoD | 1.785 / 6.00 = **29.8%** | MARGINAL |
| Worst case 單圈 DoD | 2.272 / 6.00 = **37.9%** | **FAIL** |

#### 情境 2：加熱器 0.75W

Eclipse-end 溫度估算（B-008 lumped model 推算）：

```
加熱器增加 0.25W → Eclipse 穩態極限提升：
Q_in = 4.04 + 0.75 = 4.79 W（vs 現狀 4.54W）
T_eq = (4.79 / 1.276e-9)^(1/4) = 247.3 K = -25.7°C

Eclipse-end 暫態：
T_end = 247.3 + (290.3 - 247.3) × e^(-2142/2670)
      = 247.3 + 43.0 × 0.449
      = 247.3 + 19.3 = 266.6 K = -6.5°C
```

| 項目 | 數值 |
|------|------|
| Eclipse-end 電池溫度 | **-6.5°C** |
| 溫度餘裕 | 3.5°C（改善 +1.8°C） |
| Li-ion 容量因子 (-6.5°C) | ~77%（-10°C→0°C 內插） |
| EOL effective 容量 | 10 × 0.80 × 0.77 = **6.16 Wh** |
| 加熱器額外耗電 | (0.75-0.50) × 35.7/60 = **+0.149 Wh/orbit** |
| EOL 能量收支 | -0.040 - 0.149 = **-0.189 Wh/orbit** |
| 正常 Eclipse DoD | 1.934 / 6.16 = **31.4%** | **FAIL** |
| Worst case 單圈 DoD | 2.421 / 6.16 = **39.3%** | **FAIL** |

> 注意：加熱器升至 0.75W 後，Eclipse 功耗從 3.00W 升至 3.25W，Eclipse 放電量 = 3.25 × 0.595 = **1.934 Wh**。Worst case 放電量 = 1.585 + 0.25×31.7/60 + 0.687 = 1.585 + 0.132 + 0.687 = **2.404 Wh**（Eclipse 非 contact 段也多消耗加熱器增量）。
>
> 修正：worst case 重算 = Eclipse 非 contact 段 3.25×31.7/60 = 1.717 + Contact 10.55×4/60 = 0.703 = **2.420 Wh**

#### 情境 3：加熱器 1.0W（最保守熱控方案）

```
Q_in = 4.04 + 1.0 = 5.04 W
T_eq = (5.04 / 1.276e-9)^(1/4) = 250.3 K = -22.7°C

T_end = 250.3 + (290.3 - 250.3) × e^(-2142/2670)
      = 250.3 + 40.0 × 0.449
      = 250.3 + 18.0 = 268.3 K = -4.8°C
```

| 項目 | 數值 |
|------|------|
| Eclipse-end 電池溫度 | **-4.8°C** |
| 溫度餘裕 | 5.2°C（改善 +3.5°C） |
| Li-ion 容量因子 (-4.8°C) | ~79% |
| EOL effective 容量 | 10 × 0.80 × 0.79 = **6.32 Wh** |
| 加熱器額外耗電 | 0.50 × 35.7/60 = **+0.298 Wh/orbit** |
| EOL 能量收支 | -0.040 - 0.298 = **-0.338 Wh/orbit** |
| Eclipse 功耗（含 1.0W heater） | 3.50W |
| 正常 Eclipse DoD | 3.50×0.595 / 6.32 = 2.083 / 6.32 = **32.9%** | **FAIL** |
| Worst case 單圈 DoD | ~2.56 / 6.32 = **40.5%** | **FAIL** |

### 2.3 情境比較總表

| 指標 | 0.5W（現狀） | 0.75W | 1.0W |
|------|:----------:|:-----:|:----:|
| T_min (°C) | -8.3 | -6.5 | -4.8 |
| 溫度餘裕 (°C) | 1.7 | 3.5 | 5.2 |
| Li-ion 容量因子 | 75% | 77% | 79% |
| EOL effective (Wh) | 6.00 | 6.16 | 6.32 |
| EOL 能量收支 (Wh/orbit) | -0.040 | -0.189 | -0.338 |
| 正常 Eclipse DoD | 29.8% | 31.4% | 32.9% |
| Worst case DoD | **37.9%** | **39.3%** | **40.5%** |
| 判定 | FAIL | FAIL | FAIL |

### 2.4 結論

**加熱器升級無法解決根本問題。** 原因：

1. 加熱器每增加 0.25W，溫度改善約 +1.8°C，但容量因子僅從 75% 升至 77%（+2 pp）
2. 同時加熱器額外耗電 +0.149 Wh/orbit，使 Eclipse 放電量增加，抵消容量改善
3. 三個情境的 worst case DoD 均超過 30%，且 EOL 能量赤字持續惡化
4. 這是一個 **負反饋死胡同**（negative-sum trade）：改善溫度的代價大於容量收益

## 3. 解決方案評估（Analysis C）

### Option 1：增大電池容量（DCN-002 推薦方案）

**方案**：電池從 10 Wh 升級至 **15 Wh**（如 GomSpace P60 dock 或額外 NanoPower BP4 模組）

```
EOL 容量 = 15.0 × 0.80 = 12.0 Wh
低溫 effective = 12.0 × 0.75 = 9.00 Wh（@ -8.3°C，保留 0.5W 加熱器）

放電量不變（系統功耗未改變）：
- 正常 Eclipse 放電 = 1.785 Wh
- Worst case 單圈放電 = 2.272 Wh

修正 DoD：
- 正常 Eclipse DoD = 1.785 / 9.00 = 19.8%   ✅ PASS (margin 10.2%)
- Worst case DoD = 2.272 / 9.00 = 25.2%       ✅ PASS (margin 4.8%)
```

| 評估項目 | 數值 |
|---------|------|
| 正常 Eclipse DoD | **19.8%** -- PASS |
| Worst case DoD | **25.2%** -- PASS (margin 4.8%) |
| 質量增加 | +200~300g（電池模組典型 40-50 Wh/kg） |
| 目前質量餘裕（B-004） | 1,820g（45.5%），增加後仍有 1,520~1,620g |
| 成本增加 | +$500~1,500 USD（COTS Li-ion 模組） |
| 對其他子系統影響 | 無 -- 僅 EPS 模組體積略增，3U 空間可容納 |
| EOL 能量收支 | 仍為 -0.040 Wh/orbit（功耗不變） |
| 可行性 | **高** -- 標準 COTS 升級，不影響系統架構 |

### Option 2：增加太陽能板面積（DCN-003）

**方案**：太陽能板從 6.5W 升級至 **8.0W BOL**

```
EOL peak = 8.0 × 0.9137 = 7.31 W
EOL avg = 7.31 × 0.504 = 3.68 W
EOL 每圈收入 = 3.68 × 94.5/60 = 5.80 Wh
EOL 能量收支 = 5.80 - 4.755 = +1.04 Wh/orbit  ✅ 轉正且充裕

即使加熱器升至 1.0W（額外 0.298 Wh/orbit）：
收支 = +1.04 - 0.298 = +0.74 Wh/orbit  ✅ 仍正
```

| 評估項目 | 數值 |
|---------|------|
| EOL 能量收支 | **+1.04 Wh/orbit** -- 大幅轉正 |
| 含 1.0W 加熱器收支 | **+0.74 Wh/orbit** -- 仍正 |
| DoD 改善 | 間接改善（能量充裕，可保持電池高 SoC） |
| 可行性 | **低** -- 3U body-mount 太陽能板面積受限 |

> **物理限制**：3U CubeSat body-mount 太陽能板最大面積約 0.09 m²（三面×0.034 m²/面）。三結 GaAs 效率 ~30%，理論上限 = 1367 × 0.30 × 0.09 = 36.9W（AM0 正射）。但考慮傾斜角、平均投影面積後，6.5W BOL 已接近 3U body-mount 的工程上限。升至 8.0W 需要 **展開式太陽能板（deployable solar panel）**，涉及展開機構設計、質量增加、可靠性風險。
>
> B-004 已列太陽能板為「展開式 3U Solar Panels ×2, 200g」。若現有展開板支持 8.0W 需確認面積是否足夠，否則需加大面板或增加第三組展開板。

### Option 3：限制電池放電深度（韌體方案）

**方案**：EPS 韌體設定 SoC 下限為 70%（= DoD 上限 30% 嚴格執行），低於此值自動進入 Safe Mode

```
Safe Mode 功耗 = 2.40~2.90 W（B-005 §3.1）
Safe Mode Eclipse 放電 = 2.65 × 0.595 = 1.577 Wh
Safe Mode DoD (EOL 6.00 Wh) = 1.577 / 6.00 = 26.3%  ✅ PASS

但代價：Safe Mode 無任務執行能力，可能頻繁觸發
```

| 評估項目 | 數值 |
|---------|------|
| 技術可行性 | **高** -- 純韌體修改 |
| 任務影響 | **高** -- EOL 後期可能頻繁進入 Safe Mode，任務可用率降低 |
| DoD 安全性 | ✅ 硬體層級保護 |
| 建議 | 作為**輔助方案**，搭配 Option 1 使用 |

## 4. cos_theta_avg 季節性變化分析（Analysis D）

### 4.1 Beta Angle 對 SSO 軌道的影響

500 km SSO（Sun-Synchronous Orbit）的 RAAN drift rate ≈ 0.9856°/day，設計上使軌道面隨太陽旋轉。但由於地球軌道橢圓性和其他攝動，beta angle 不完全固定，典型漂移範圍：

| 參數 | 值 |
|------|:--:|
| SSO 設計 beta angle | ~0°（Local Time descending node 固定） |
| Beta angle 實際漂移範圍（500 km SSO） | **-20° ~ +20°** |
| B-005 基線 cos_theta_avg | 0.90（隱含 beta ≈ 0°） |

### 4.2 cos_theta_avg 與 Beta Angle 的關係

Body-mount 太陽能板的軌道平均有效照射隨 beta angle 變化：

```
cos_theta_avg(beta) ≈ cos_theta_avg(0°) × cos(beta) × correction_factor

beta = 0°  : cos_theta_avg ≈ 0.90  （B-005 基線值）
beta = ±10°: cos_theta_avg ≈ 0.88
beta = ±15°: cos_theta_avg ≈ 0.86
beta = ±20°: cos_theta_avg ≈ 0.84
```

### 4.3 Worst Case EOL 能量收支（beta = ±20°）

```
EOL peak power = 5.939 W（不變）
EOL avg power = 5.939 × (1 - 0.3778) × 0.90(MPPT) × 0.84(cos_theta worst)
              = 5.939 × 0.6222 × 0.90 × 0.84
              = 5.939 × 0.4703
              = 2.793 W

EOL 每圈收入 = 2.793 × 94.5/60 = 2.793 × 1.575 = 4.399 Wh
每圈支出 = 4.755 Wh（不變）

Worst case EOL 能量收支 = 4.399 - 4.755 = -0.356 Wh/orbit
```

### 4.4 季節性赤字累積效應

| Beta Angle | cos_theta_avg | EOL avg (W) | 每圈收入 (Wh) | 收支 (Wh/orbit) |
|:----------:|:-------------:|:-----------:|:-------------:|:---------------:|
| 0° | 0.90 | 2.993 | 4.715 | -0.040 |
| ±10° | 0.88 | 2.927 | 4.610 | -0.145 |
| ±15° | 0.86 | 2.860 | 4.505 | -0.250 |
| ±20° | 0.84 | 2.793 | 4.399 | **-0.356** |

**Worst case 赤字 -0.356 Wh/orbit 的意義**：
- 電池每圈額外放電 0.356 / 6.00 = 5.9% DoD（以 EOL -8.3°C effective 容量計）
- 若無 mitigation，約 **5 圈（~7.9 小時）** 即耗盡 30% DoD 限值
- 需要 M1（降 contact duty cycle）**和** M2（OBC clock gating）**同時啟用**

### 4.5 M1 + M2 Mitigation 在 Worst Case Beta Angle 下的效果

| Mitigation | 節省 (Wh/orbit) | 來源 |
|-----------|:---------------:|------|
| M1：每 2 圈 contact 1 次 | +0.343 | B-005 §7.3（支出從 4.755 降至 4.412） |
| M2：OBC standby 1.5→1.2W | +0.428 | B-005 §7.3（0.3W × 1.428hr） |
| **M1 + M2 合計** | **+0.771** | |

```
Worst case (beta=20°) + M1 + M2：
收支 = -0.356 + 0.771 = +0.415 Wh/orbit  ✅ PASS

Worst case (beta=20°) + M1 only：
收支 = -0.356 + 0.343 = -0.013 Wh/orbit  ❌ 仍微負

Worst case (beta=20°) + M2 only：
收支 = -0.356 + 0.428 = +0.072 Wh/orbit  ✅ 勉強轉正
```

### 4.6 結論

- **B-005 的 cos_theta_avg = 0.90 為名目值**，未考慮 beta angle 季節性漂移
- Worst case（beta = ±20°）下，EOL 赤字可達 **-0.356 Wh/orbit**（vs 名目 -0.040）
- **單獨 M1 不夠**（仍微負），需 **M1 + M2 同時啟用** 或至少 M2 單獨啟用
- 若採用 DCN-002（15 Wh 電池），電池更大但 EOL 能量赤字仍存在 -- **DCN-002 解決 DoD 問題，但不解決能量赤字問題**
- 能量赤字需靠 **operational mitigation（M1/M2）** 處理
