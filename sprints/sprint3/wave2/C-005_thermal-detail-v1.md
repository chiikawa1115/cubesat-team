## 2. 熱點 A：PA 散熱詳細分析

### 2.1 PA 元件規格

| 參數 | 數值 | 備注 |
|------|------|------|
| 型號 | PMA3-43-1W+ | Mini-Circuits |
| 封裝 | QFN，3×3 mm | 底部曝露焊盤（exposed pad）|
| RF 輸出功率 P_out | 1 W | 滿功率 |
| DC 輸入功耗 P_DC | 4 W | 由 EPS 12V boost 供電，IF-12 |
| 熱耗散 Q_PA | **3 W** | = P_DC × (1 - PAE) = 4 × 0.75 |
| 最高 Junction 溫度規格 | +150°C | 器件數據手冊 |
| 操作模式 | 接觸窗口（4 min/orbit）期間全功率 | B-002 §5.1 |

### 2.2 熱阻路徑分析

PA 熱流路徑為：**PA Junction → QFN Exposed Pad → PCB via array → PCB GND plane → 結構框架螺柱 → 鋁結構框架 → 外表面輻射散熱**

```
[PA Junction]
      │
      │ θ_jc = 15°C/W（Junction to Case，QFN 典型值）
      ▼
[QFN Exposed Pad / PCB 頂層銅]
      │
      │ θ_via = 1.4°C/W（6×6 = 36 vias，各 ~50°C/W 並聯）
      ▼
[PCB GND 平面（底層銅）]
      │
      │ θ_mount = 5°C/W（PCB 與結構框架螺柱接觸）
      ▼
[Al 6061 結構框架]
      │
      │ θ_frame = 2°C/W（鋁框架內部傳導至外表面）
      ▼
[外壁散熱面] → 輻射至太空
```

各熱阻值：

| 熱阻段 | 符號 | 數值（°C/W）| 計算依據 |
|--------|------|------------|---------|
| Junction to Case | θ_jc | 15.0 | QFN 封裝典型值 |
| PCB via array（36 vias 並聯）| θ_via | 1.4 | 50 / 36 = 1.39 ≈ 1.4 |
| PCB 到結構框架（螺柱接觸）| θ_mount | 5.0 | 估算，含接觸熱阻 |
| 結構框架導熱 | θ_frame | 2.0 | 鋁 6061，k = 167 W/m·K |
| **總熱阻 θ_total** | | **23.4** | 串聯相加 |

### 2.3 PA Junction 溫度計算

**穩態工況**（Contact Window 期間環境溫度 +24.7°C）：

```
T_junction = T_ambient + Q_PA × θ_total
           = 24.7 + 3 × (15.0 + 1.4 + 5.0 + 2.0)
           = 24.7 + 3 × 23.4
           = 24.7 + 70.2
           = 94.9°C
```

**器件餘裕核查**：

| 項目 | 數值 |
|------|------|
| 計算 T_junction | +94.9°C |
| 器件最高 T_junction 規格 | +150°C |
| 餘裕（Margin）| **+55.1°C** |
| 判定 | **PASS** |

PA Junction 溫度 94.9°C，距規格上限 150°C 具有 55.1°C 裕度，PA 本身不構成熱控風險。

### 2.4 接觸窗口 4 min 暫態 PCB 溫升

Contact Window 持續 4 min（240 s），遠小於系統熱時間常數（B-008 §4.7 估算 τ ≈ 44.5 min）。PCB 局部因 PA 的持續 3W 熱耗散會產生溫升。

**RF PCB 熱容估算**（FR4，4 層板，尺寸 95×90×1.0 mm）：

```
m_pcb = 0.095 × 0.090 × 0.001 × 1850 kg/m³ = 0.0158 kg = 15.8 g
C_p(FR4) ≈ 1150 J/kg·K
C_thermal_pcb = 0.0158 × 1150 = 18.2 J/K
```

**無散熱時最大溫升**（4 min 全部熱量儲存在 PCB）：

```
Q_total = 3 W × 240 s = 720 J
ΔT_pcb_max = Q / C_thermal = 720 / 18.2 = 39.6°C
```

**有 via array 散熱時實際溫升**：

via array（36 vias）提供主要熱傳路徑。估算約 70% 熱量透過 via 傳導至結構框架散出，僅 30% 短暫儲存在 PCB：

```
Q_stored = 720 × 30% = 216 J
ΔT_pcb_actual = 216 / 18.2 ≈ 11.9°C → 取保守值 ΔT ≈ 15°C
```

**接觸窗口後 PCB 溫度**：

```
T_pcb_peak = T_ambient + ΔT_pcb
           = 24.7 + 15.0
           = 39.7°C
```

**符合性評估**：

| 項目 | 數值 | 需求 | 判定 |
|------|------|------|------|
| PCB 峰值溫度（初始 6×6 via）| +39.7°C | ≤+40°C（SYS-012）| ⚠ 裕度僅 0.3°C |

**結論**：4 min 接觸窗口後，RF PCB 溫度約達 +39.7°C，距操作溫度上限 +40°C 裕度僅 **0.3°C**，不足以應對製造公差、熱阻估算誤差及壽命衰退等不確定因素。**需採取緩解措施**。

### 2.5 緩解措施

**方案 1：Via array 密度升級（6×6 → 8×8）**

| 參數 | 現行（6×6）| 升級後（8×8）|
|------|-----------|------------|
| Via 數量 | 36 | 64 |
| θ_via | 1.4°C/W | 50/64 = **0.78°C/W** |
| 散熱能力提升 | 基線 | 更高，散熱效率約提升 15–20% |
| 預估散熱比例 | 70% | ~80% |
| 估算 ΔT_pcb | 15°C | ~10°C |
| PCB 峰值溫度 | +39.7°C | **+34.7°C** |

**方案 2：RF PCB 直接螺鎖外壁鋁板**

RF PCB 固定螺柱改為鋁製，並在 PCB 底面與外壁鋁板之間加設導熱膠墊（TIM），降低 θ_mount（目標 5°C/W → 2°C/W），提供直接傳導散熱路徑至衛星外壁。

**建議採用方案 1 + 方案 2 組合**：

| 改善項目 | 效果 |
|---------|------|
| Via 升級至 8×8（64 vias）| θ_via 降至 0.78°C/W，散熱比例提升至 ~80% |
| PCB 直接螺鎖外壁鋁板（TIM pad λ ≥ 2 W/m·K）| θ_mount 降至 ~2°C/W，增加傳導面積 |
| **組合後估算 T_pcb_peak** | **≈ +34.7°C（裕度 +5.3°C）** |

### 3.3 Eclipse 熱平衡細化（B-008 §4.7 延伸）

Eclipse-end 溫度 -8.3°C 計算基礎（摘自 B-008 v1.1 §4.7）：

```
T_eclipse-end = 244.2 + (290.3 - 244.2) × exp(-2142 / 2670)
              = 244.2 + 46.1 × 0.449
              = 244.2 + 20.7
              = 264.9 K = -8.3°C
```

其中：
- T_eq（含加熱器）= 244.2 K（-28.9°C）
- T_sunlit = 290.3 K（+17.2°C）
- τ = 2670 s（44.5 min）
- Eclipse 時長 = 2142 s（35.7 min）

**電池溫度餘裕**：-8.3°C 對 -10°C 下限，餘裕 **1.7°C**（偏小，見 §3.6 風險評估）。

### 3.4 加熱器詳細設計

| 項目 | 規格 | 說明 |
|------|------|------|
| 加熱器型式 | Kapton 薄膜加熱器 | 柔性，可貼合電池外表面 |
| 加熱器尺寸 | 20×30 mm | 覆蓋電池底面 |
| 功率 | 0.5 W/片 | 一用一備（2 片共 0.5 W 單路）|
| 安裝位置 | 電池模組底面（靠近結構框架冷面）| 直接熱接觸 |
| 控制方式 | OBC 讀取 PT100 溫度感測器 → GPIO MOSFET 開關 | B-002 IF-07 |
| 啟動門檻 | T_battery < -5°C → 觸發（留 5°C buffer 至 -10°C 下限）| B-008 §6.3 |
| 關閉門檻 | T_battery ≥ 0°C | 避免頻繁切換 |
| 感測器 | PT100（鉑電阻溫度計）×2，電池上/下面各 1 | 冗餘量測 |
| 冗餘設計 | 加熱器 ×2 片，獨立 GPIO 控制通道 | 任一片失效仍可加熱 |
| 每軌耗能 | 0.5 W × 35.7 min / 60 ≈ **0.30 Wh/orbit** | B-008 §6.2 確認一致 |

**控制邏輯流程**：

```
OBC（1 Hz 採樣）
      │
      ├─ T_battery < -5°C → GPIO High → MOSFET ON → 加熱器通電（0.5W）
      │
      └─ T_battery ≥ 0°C  → GPIO Low  → MOSFET OFF → 加熱器斷電
```

### 3.5 季節性最壞情況分析（Beta angle 修正）

**Beta angle 效應**：SSO 10:30 軌道在冬至附近（局部冬季最差情況）beta angle ≈ ±20°，日照角度偏移導致太陽能板有效輸入功率下降。

| 參數 | 標稱值 | 冬至最壞情況 |
|------|--------|------------|
| cos_theta_avg | 1.0（正常）| **0.65**（beta angle ±20° 修正）|
| 太陽能板輸入功率 | 6.5 W | 6.5 × 0.65 = **4.23 W** |
| vs 平均 4.5 W 差異 | — | -0.27 W |
| Eclipse 期間額外熱虧損 | — | 約 0.27 W |

**Eclipse-end 溫度修正估算**：

額外熱虧損 0.27 W 相當於加熱器有效功率從 0.5 W 降為 0.23 W（或等效為系統散熱略增）。以近似線性修正估算溫度影響：

```
ΔT_seasonal = 0.27 × (T_heater_effect / P_heater)
            ≈ 0.27 × (3.8°C / 0.5 W)
            ≈ 0.8°C（溫度下降）

T_eclipse-end（冬至）≈ -8.3 - 0.8 = -9.1°C
```

**季節性最壞情況評估**：

| 工況 | Eclipse-end 溫度 | 下限（SYS-012）| 餘裕 | 判定 |
|------|----------------|--------------|------|------|
| 標稱（B-008）| -8.3°C | -10°C | 1.7°C | PASS |
| 冬至最壞情況 | **-9.1°C** | -10°C | **0.9°C** | PASS（偏緊）|

**結論**：即使考慮季節性最壞情況，電池溫度仍維持在 -9.1°C > -10°C 下限，符合 SYS-012。但 0.9°C 的裕度偏小，需在 Phase B 詳細熱模型（Thermal Desktop/ESATAN）中確認。

### 3.6 低溫餘裕風險評估

| 風險因素 | 溫度影響 | 說明 |
|---------|---------|------|
| 加熱器控制精度（±2°C）| -2°C | 恆溫器滯後效應 |
| 熱時間常數模型誤差（±10%）| ~-0.5°C | Lumped-mass 簡化 |
| MLI 安裝品質差異 | -0.3 ~ -1°C | AIT 安裝品質依賴 |
| 季節性（冬至）| -0.8°C | 見 §3.5 |
| **累積最壞情況** | **可能達 -4.3°C** | 若多因素疊加 |

**潛在最壞情況**：-8.3 - 4.3 = **-12.6°C**，理論上可能低於 -10°C 下限。

**建議對策**：
1. **提升加熱器功率至 0.75 W**（B-008 §8.2 已列為 OPEN 風險，建議評估）
2. Phase B 使用 Thermal Desktop 進行 3D 節點模型，取代 Lumped-mass 估算
3. PT100 感測器採 2 點冗餘，確保控制可靠性

## 4. A_rad 修正（回應 B-008 Prof. Challenger P5 疑問）

### 4.1 B-008 使用的 A_rad 數值

B-008 §4.1 採用：A_rad = **0.025 m²**（含端面 + MLI 洩漏，保守估算）

### 4.2 更完整的表面積計算

**3U CubeSat 外表面積核算**（3U：340 × 100 × 100 mm）：

| 面 | 尺寸 | 面積 | 數量 | 小計 |
|----|------|------|------|------|
| 長面（+X, -X, +Y, -Y）| 340 × 100 mm | 34,000 mm² | 4 | 136,000 mm² |
| 端面（+Z, -Z）| 100 × 100 mm | 10,000 mm² | 2 | 20,000 mm² |
| **總外表面積** | | | | **156,000 mm² = 0.156 m²** |

**有效輻射面積（A_rad）評估**：

| 區域 | 說明 | 面積 |
|------|------|------|
| MLI 覆蓋長面（4 面）| ε ≈ 0.02，幾乎不輻射 | 不計入 A_rad |
| +Z 端面（地球朝向面，Black paint）| ε = 0.90，主要散熱面 | 0.010 m² |
| -Z 端面（反地球面，Black paint）| ε = 0.90，次要散熱面 | 0.010 m² |
| MLI 洩漏（接縫 + 螺絲孔等）| 估算洩漏 ~12% 面積 | 0.020 m² |
| **修正後有效輻射面積** | | **A_rad ≈ 0.040 m²** |

### 4.3 修正影響評估

| 參數 | B-008 使用值 | 修正值 | 差異 |
|------|------------|--------|------|
| A_rad | 0.025 m² | 0.040 m² | +60%（修正值更大）|
| σ × ε × A_rad | 1.276×10⁻⁹ W/K⁴ | 2.041×10⁻⁹ W/K⁴ | — |

**對 Eclipse-end 溫度影響**：

修正後 A_rad 更大 → 散熱能力更強 → Eclipse 穩態溫度略高（散熱更多，但衛星也更快平衡）。由於 Eclipse 持續 35.7 min < τ，暫態主導，修正 A_rad 對 Eclipse-end 溫度影響有限，方向為**略微升溫**（更多散熱面積反而讓冷卻略快，但同時增加太陽能板外輻射導致略微降溫）。

**結論**：
- B-008 採用 A_rad = 0.025 m² 為**保守值**（實際輻射面積更大）
- 修正後 A_rad = 0.040 m²，系統散熱能力較 B-008 估算更好
- Eclipse-end 溫度 -8.3°C 可能因更大 A_rad 略有修正，但加熱器補償機制維持 ≥-10°C 的判斷方向不變
- **建議 Phase B 以 A_rad = 0.040 m² 更新 Thermal Desktop 模型**
